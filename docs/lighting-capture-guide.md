# 灯效抓帧对照清单

目标：用 5 组**单变量**对照，把 `B21PayloadWriter` 的 CMD 2 报文字段逐一定位。
背景与已解析的结构见 [lighting-hid-analysis.md](lighting-hid-analysis.md)。

## 准备

1. 启动原厂「小米 G 控制中心」，停在**键盘灯效**页，别切走。
2. 确认键盘背光是**开着**的。
3. 记下当前状态（做完要还原）：效果、亮度、速度、方向、颜色。
4. 打开一个 PowerShell 窗口，`cd` 到本仓库的 `scripts` 目录。

每做一步，运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\capture-light-frames.ps1 -Label "第1步 亮度 2->1"
```

脚本会记下日志位置，然后等你去改；改完（**记得点「应用」**）回来按回车，
它只打印这一步新增的 HID 报文，并把同命令的相邻帧逐字节对比。

## 五个对照

按顺序做，**每一步只改一项**，其余全部保持不变。

| 步 | 改什么 | 从 → 到 | 目的 |
| ---: | --- | --- | --- |
| 1 | 亮度 / 强度 | 2 → 1 | 定位亮度字段 |
| 2 | 速度 | 1 → 3 | 定位速度字段 |
| 3 | 方向 | 2 → 4 | 定位方向字段 |
| 4 | 颜色 | 青蓝 → 红 | 定位颜色类型 / 颜色值 |
| 5 | 键盘灯开关 | 关 → 开 | 校验方法（已知会改第 5/7/9 字节） |

**第 4 步建议**：先把效果切成「静态」，这样颜色是最直接的变量，不受动态效果干扰。

## 每一步的注意事项

- 只改一项。如果手滑改了两项，这一步作废，改回去重做。
- 改完一定要点「应用」；只拨动滑块不点应用，可能只写注册表、不发 HID。
- 改完等 1～2 秒再按回车，让工作线程把帧发完。
- 不要在抓帧过程中切换页面，否则会混入 `CMD 13` 之类的页面事件。
- 某一步如果脚本报告「没有产生任何 HID 报文」，**这本身就是有用信息**，照实告诉我。

## 需要回传什么

把每一步脚本的完整输出贴回来。格式大概是这样：

```
2026-10-31 22:25:11,850  CMD 2  len=65
  0057AB020101000102010000B3000…
  与上一条同命令帧的差异: [12] B0->B3
```

含 `CMD 0`（心跳）是正常的——心跳的字节不会变，正好用来确认时序没串。

## 做完之后

我会用这 5 组对照确定 CMD 2 的位域，然后才决定是否实现 HID 写入。写入需要：

- 独占一个 65 字节报文的 HID 设备句柄；
- 完整复现编辑态时序（`CMD 12:1` → 若干 `CMD 2` → `CMD 12:0` → `CMD 5`）；
- 先用 `GetEffectParams` 做读回校验，再写。

在这三件事都验证之前，本软件不会碰键盘背光。
