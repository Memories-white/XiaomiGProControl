# 逐键屏幕映射与键盘频谱柱

## 已实现的流程

动态效果可选择统一 RGB 或逐键输出。逐键屏幕联动将主屏幕缩放为 7×17 颜色矩阵，
采样密度 1–5；音频使用现有 WASAPI/FFT 的 17 个频段绘制四方向频谱柱，提供四组原厂渐变。
界面提供实际生成帧的矩阵预览。单色音量呼吸也可通过逐键通道输出。

首次使用需点击“校验逐键灯效（16 秒）”：

1. 前八秒：左侧红色、中间绿色、右侧蓝色。
2. 后八秒：白色光带横向移动。
3. 自动恢复原灯效，然后由用户选择实际显示是否正常。

选择“显示正常”后将 `RealtimeLightingValidated` 保存到本机配置，开放逐键选项。
选择异常或暂不确认则继续使用统一颜色。离开校验页会取消测试并执行恢复。
该确认只代表用户观察结果，不被描述为硬件颜色读回。

## 原厂静态证据

原厂 `libXiaomiGCommandCenter.dll` 2.1.1.418，复用已有 Ghidra 工程。
以下是 Ghidra 反编译观察，不是 REA MCP 运行时证据：

| 地址 | 已观察到的行为 |
| --- | --- |
| `0x180189240` → `0x18018a2c0` | DrawManager 初始化 7 行、17 列的 Point 矩阵 |
| `0x1801891a0` → `0x180181550` → `0x180181450` → `0x1801818f0` → `0x180181980` → `0x180181920` → `0x180182440` | Point 构造时 `+7=0`（dirty）、`+8=1`（valid）；默认矩阵119个虚拟位置都标记有效 |
| `0x1801241c0` | CMD 4 每包最多12条 `[row*17+column,7F,R>>1,G>>1,B>>1]`；不足12条的末包以 FF 结束 |
| `0x1801251a0` | 读取 CMD 1，效果字段设置为0，再发送 CMD 2；不发送 CMD 5 |
| `0x180120b20` / `0x1801209b0` | 心跳循环约每秒调度一次，空 CMD 0，OperatorType 1（只写） |
| `0x1801221c0` | OperatorType 1 只发送，不读回复；CMD 4 也使用该类型 |

119 是协议矩阵位置数，并不表示实体键盘有119个按键。原厂默认有效标记证明初始发送范围，
实体位置、颜色与方向仍需观察。本版没有通过 CMD 1 推断独立按键颜色。

## 传输与恢复

`B21RealtimeSession` 在版本01.13和LED区域B通过检查后备份 CMD 1、进入实时模式并读回确认。
CMD 4 与 CMD 0 使用持续打开的 HID 句柄只写，不等待不存在的颜色确认。
会话与普通控制共享命令锁，独占实时会话租约。会话期间拒绝普通 CMD 2/5 写事务；
启动失败由逐键会话自身回滚，禁止把实时模式写进闪存。窗口或托盘退出会取消并等待校验清理。
异常或取消均进入恢复路径。
动画帧不发送 CMD 5；正常停止时恢复备份的常规灯效，并进行状态验证。

旧设置默认继续使用统一颜色。逐键选项需要本机显示确认，未经确认不会通过预设默认打开。
采集与生成颜色只在内存中处理；停止时释放音频/GDI资源和清空预览。

## 已执行的验证与边界

- 离线：0/1/11/12/13/24/119个像素的包边界、7bit颜色缩放、哨兵、重复/越界拒绝。
- 渲染：四方向及镜像、静音/NaN、不同频段独立颜色、混合频带高度和最低亮度非零。
- 实机报文：16秒发送227帧，实时模式保持，最后状态块及RGB数据恢复。
- 实机循环：四方向音频频谱循环、屏幕采样密度1/5各通过；采样帧分别有116/115种颜色。
- 实体颜色/位置：CMD 4 无已知独立颜色读回，仍需用户观察确认。本轮音频循环为静音，不能据此声称实体频谱动画已目视通过。

```powershell
dotnet run --project tests/GProControl.PixelTests -c Release
dotnet run --project tests/GProControl.LightingProbe -c Release -- --validate-realtime
dotnet run --project tests/GProControl.LightingProbe -c Release -- --validate-per-key-effects
```

后两个命令会短暂改变键盘灯并恢复。原始本机日志在忽略目录 `analysis-runtime/`。
